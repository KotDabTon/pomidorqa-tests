## По кодексу

* [ ] **1. Где лежит.** Сценарий в `e2e`, пользователь в `helpers`, экран в `pages`. Регистрация не в `ProfilePage` и не в `BookingPage`. Локаторы не в spec, если соответствующая страница есть.
* [ ] **2. Вынос.** Дублирование вынесено. Метод страницы описывает действие (`saveName`). `expect` находится в тесте.
* [ ] **3. Каркас.** `describe` = фича, `test` = проверка. `beforeEach`: свой пользователь + страница.
* [ ] **4. Степы.** Каждый шаг и проверка — `test.step` с понятным названием. В проверочном степе нет кликов. Страница открывается в шаге или хуке.
* [ ] **5. Имена.** Название описывает, что проверяется, а не техническое действие вроде `fill input`.
* [ ] **6. Нарезка.** Связанные проверки после одного Act не размазаны на микротесты без необходимости. И наоборот: один тест не объединяет несколько несвязанных сценариев.
* [ ] **7. Данные.** Для каждого теста используются собственные данные через `makeUser`. Пароль можно хардкодить, имя и почта — нет.
* [ ] **8. Локаторы.** Приоритет: role / label / testid. Повторяющийся якорь находится в Page Object, а не копируется в spec.
* [ ] **9. Ожидания.** Нет `timeout` / `force` / `.only` / `pause`. Нет `expect` сразу после `fill` без сохранения и необходимого обновления состояния.
* [ ] **10. Гейт.** Тесты зелёные, линт проходит, описание PR заполнено.
* [ ] **11. API Arrange.** Регистрация и другой сетап выполняются через API, если UI этого действия не является предметом теста.
* [ ] **12. Cleanup.** Созданные аккаунты удаляются через `finally` или гарантированный `afterEach`. Контексты регистрируются для cleanup до первого действия, которое может упасть. Вместе с аккаунтами удаляются связанные навыки, слоты и бронирования.

## Не придирайся

Кавычки, форматирование и lockfile — не повод для комментария сами по себе.

Другое имя метода при том же смысле — допустимо.

Скриншоты и моки не требуются без необходимости.

`BookingPage` используется там, где его методы действительно относятся к сценарию бронирования.
