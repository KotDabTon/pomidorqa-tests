# Матрица покрытия PomidorQA

Покрытие считается по функциональным требованиям MVP из `requirements.md`, а не по числу
файлов или тестов. Продукт проверяется как чёрный ящик: исходников `aiqa.su/pomidorqa`
в репозитории нет, поэтому code coverage не измеряем.

| Статус         | Что означает                                                                                                                  |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `automated`    | требование полностью подтверждено автоматическим тестом непосредственно на реальном `aiqa.su/pomidorqa`                       |
| `partial`      | автоматизирована только часть требования либо доказательство относится к локальному mock/unit-коду, а не к реальному продукту |
| `known defect` | продукт не выполняет требование; дефект подтверждён на живом стенде, тест переведён в `test.fail()`                           |
| `out of scope` | требуемое состояние недостижимо через доступный black-box интерфейс, поэтому полная проверка невозможна                       |

Срез обновлён **21.09.2026**, ветка регрессии, стенд `https://aiqa.su/pomidorqa`.

## Уровни проверок

| Уровень | Тестов | Что реально проверяет                                                                            |
| ------- | -----: | ------------------------------------------------------------------------------------------------ |
| unit    |     10 | чистые функции курса: пересечение слотов, валидация пароля, формат времени — **не код продукта** |
| api     |      8 | бизнес-правила бронирования и регистрации на мок-сервере курса (`src/pyramid/mock-booking-api`)  |
| e2e     |     38 | пользовательские сценарии в браузере на реальном `aiqa.su/pomidorqa`                             |

Unit-уровень и API-уровень в основном проверяют инфраструктуру курса, а не код продукта.
Реальное покрытие продукта обеспечивает преимущественно e2e-уровень. Unit/API-тесты
при этом остаются частью набора проверок, поскольку проверяют отдельные бизнес-правила и
тестовую инфраструктуру.
